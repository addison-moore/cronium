# Changelog - 2026-07-18

- [2026-07-18] [Refactor] Styling Phase 2 — canonical status semantics (per `_plans/styling/Review.md` §4). `status-badge.tsx` is now the single status module: a 6-theme table (success/destructive/warning/info/neutral/brand) built purely on semantic tokens, a status→theme+icon map covering event/log/user/job statuses plus lowercase aliases, and a new exported `StatusIcon` for icon-only surfaces. Canonical mapping enforced everywhere: success=green `CircleCheck`, failure=red `CircleX` (was variously XCircle/AlertCircle/AlertTriangle), running=blue `Loader2` spinning (was RefreshCw/Clock), pending/draft=gray static `Clock`, warning/paused/timeout/partial=amber (collapsing the yellow/amber/orange split), info=blue (resolving the indigo-badge vs blue-token collision). Migrated the ad-hoc status renderers to it (JobsTable, JobStatusCard, WorkflowExecutionGraph, action-builder PreviewPanel/ActionNode, WorkflowsCard, EventOverviewTab, DashboardStats, events-table run button) and tokenized the React-Flow canvases — ConnectionEdge/ActionEdge/Canvas/WorkflowCanvas hex literals became `var(--success-color)` etc., so edges/minimap/grid now follow dark mode (ConnectionEdge also dropped its `useTheme` dependency). Added status _on-tint text_ tokens (`--success/warning/destructive/info-text-color` + light/dark values) for readable label text on translucent fills, and brightened dark-mode `--destructive` from #b91c1c to #ef4444 (shadcn-style; the old value had ~2.5:1 text contrast on dark). Swept raw status-hue palette classes app-wide (error panels, form errors, filter dots, bulk-action buttons, auth pages, admin notifications): status-meaning raw classes reduced from ~600 occurrences to 20, all brand/terminal-specific. Verified: typecheck, lint, 248 tests, and production builds of both apps green; new utilities confirmed present in compiled CSS.
- [2026-07-18] [Fix] `next build` static export: removed `NODE_ENV=development` from `env/.env.local` and both env templates (the app's dotenv-wrapped build script leaked it into the export workers, which then loaded React's _development_ edge runtimes against Next's compiled production pages runtime — crashing /404 & /500 prerender with "<Html> should not be imported outside of pages/_document" and client components with a null hooks dispatcher). Next.js manages NODE_ENV itself; `env.mjs` now defaults NODE_ENV to "development" for processes launched outside the Next CLI (socket server via tsx). Combined with the @anthropic-ai/sdk externalization, `pnpm build` for cronium-app fully passes again.
