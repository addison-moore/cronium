# Changelog - 2026-07-13

- [2026-07-13] [Refactor] Tools/Plugins Phase 3 (modularity). (3.A) Unified the four parallel server-side tool registries — the action registry, the credential-schema switch, the connection-test switch, and the OAuth-config map, each of which re-listed every tool — into a single manifest-driven registry (`lib/tools/tool-registry.ts`). A tool is now described once by a server-safe `manifest.ts` (type, credential schema, actions, connection test, optional OAuth), and adding a tool means creating its folder and adding one import to the registry's `MANIFESTS` list; nothing else on the server changes. Extracted each tool's connection test into its own `<tool>/connection-test.ts` (out of the old central switch) and added shared helpers (`lib/tools/connection-test.ts`: `fetchWithTimeout`, `testFailure`). Deleted `lib/tools/server-plugin-actions.ts` and `tools/plugins/validation-registry.ts`. (3.B) Router cleanup: deleted the dead per-tool tRPC plumbing that the generic `tools.*` endpoints already replaced — `buildPluginRouter`/`plugin-router.ts`, the six non-Slack `*-routes.ts` routers (discord/email/google-sheets/teams/notion/trello — zero client callers), all seven plugin `api-routes.ts` files and the `apiRoutes` field/`PluginApiRoute*` types that only `buildPluginRouter` consumed. Kept Slack's router (two live UI calls) and repointed its connection test to the unified registry. Net: ~14 files removed, one source of truth for what a tool is. (3.C) Hardened and proved the new model: the registry now throws at module load if two tools declare the same action id (previously a silent shadow in the global action map, and stored events route by id, so a collision could misfire an action); made `tools.getStats.byType` derive counts from the tools themselves instead of a hardcoded slack/discord/email trio that omitted the other four types. Ran a drop-in acceptance test — a synthetic `github` tool registered, its action became routable, and credential validation worked with only a new folder plus one import + one array entry in the registry, zero edits to any tRPC router or API (then removed). Verified: typecheck, lint, and a production build all pass.

- [2026-07-13] [Bug Fix] Tools/Plugins Phase 2 (reliability). (2.1) Tool actions no longer report failures as success: every plugin action returned `{success:false}`/`{ok:false}` instead of throwing, so a failed Slack/Discord/Teams/Notion/Trello/Sheets send was marked SUCCESS and the retry/circuit-breaker never fired. The executor now converts a failure result to a thrown error → the job fails honestly (exitCode 1) and the breaker records it. (2.5) Since that enables the previously-dead retry, and tool sends are non-idempotent, the tool-action retry is capped at a single attempt to avoid double-delivery (idempotent retry with keys is future work). (2.2) Added `socketTimeout` to the email transport so a mid-send stall can't hang a job (HTTP calls got timeouts in Phase 1.1). (2.4) The circuit breaker is now functional (post-2.1); documented that its state is per-process/in-memory. (2.6) Removed the dead connection-pool call from the executor and deleted `lib/tools/connection-pool.ts`. (2.3) Found the primary `TOOL_ACTION`-event container path (`cronium/tool-executor:latest`) is dead — no image, no orchestrator handler, no UI to create such events; the real path is in-process and now hardened. Consolidation deferred to the architecture phase.

- [2026-07-13] [Security] Tools/Plugins Phase 1 (security hardening). (1.1) SSRF: all outbound tool requests now go through a `safe-fetch` guard (https-only, exact per-tool host allowlist, private/loopback/link-local IP rejection, no redirects, timeout) — closing webhook SSRF in Slack/Discord/Teams where a user could point a webhook at cloud-metadata or internal addresses. (1.2) Decrypted credentials are no longer returned to the browser: the tool read endpoints blank secret fields, and edits merge blank secrets with the stored value ("leave blank to keep") so nothing is wiped. (1.3) OAuth access/refresh tokens are now encrypted at rest (AES-256-GCM) instead of plaintext. (1.4) Secret-bearing parameters/results are redacted before being logged or persisted to `toolActionLogs`. (1.5) The rate limiter/quota now fail closed instead of open, the quota sums real request counts instead of counting window rows, and the manual `executeAction` path is throttled. (1.6) Low-entropy ENCRYPTION_KEY now warns at init; documented the KDF salt as intentionally static. Deferred with notes: the atomic-window rate-limit race (needs a schema change) and the "optional secret on edit" form UX (belongs with the form work).

- [2026-07-13] [Bug Fix] Tool actions failed at runtime with "Action not found" (e.g. Slack `slack-send-message` on a scheduled event). The tool plugins are `"use client"` modules, so when server code (the scheduler, the OAuth bridge, the `executeAction` tRPC endpoint) imported the plugin objects to read their actions, Next.js handed back client reference proxies with no usable `execute()` — the server action registry came back empty. Fixed by adding a server-safe registry (`src/lib/tools/server-plugin-actions.ts`) that imports each plugin's action definitions directly from their non-client `actions` modules, never through the `"use client"` plugin objects. Extracted email's inline actions into a server-safe `email/actions.ts`, and moved the Google Sheets OAuth config into a server-safe `plugins/oauth-config.ts` (same root cause: the OAuth bridge read `requiresOAuth` off a proxy, so Google Sheets never received its token). Repointed the scheduler executor, the OAuth credential bridge, and the `tools.executeAction` tRPC mutation to the server-safe registry. Verified all 15 actions resolve with real `execute` functions.
- [2026-07-13] [Bug Fix] Silenced two webpack build warnings in `cronium-app`. (1) `Critical dependency: the request of a dependency is an expression` from `@cronium/ui`: `code-viewer.tsx` loaded the Prism line-numbers plugin via `import(variable)`, which webpack can't statically resolve. Restored a static `import("prismjs/plugins/line-numbers/prism-line-numbers")` and added an ambient module declaration (`packages/ui/src/prismjs-plugins.d.ts`) so it still type-checks despite `@types/prismjs` not covering plugin submodules. (2) `Can't resolve 'pg-native'`: added `"pg-native": false` to the client webpack `resolve.fallback`, alongside the existing `util/types`/`dns` stubs — `pg`'s native binding is an optional dependency we don't install, and it's only reached through a server-executed dynamic import inside a `"use client"` tool plugin. Verified: a production build goes from 3 warnings to 0 ("Compiled with warnings" no longer appears).
