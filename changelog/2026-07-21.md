# 2026-07-21

- [2026-07-21] [Plan] Added `_plans/security/PLAN.md`, a consolidated phased remediation roadmap for every vulnerability and operational residual remaining across both security audits, with deduplicated finding traceability, fail-closed greenfield migration policy, phase exit gates, and independent release-retest criteria.
- [2026-07-21] [Security] Implemented Phase 0 containment: made the adversarial Jest project blocking in CI; added shared Valkey socket replay/revocation with continuous terminal authorization checks; enforced tenant relationship invariants in migration `0003`; made production socket routing loopback/proxy-only; supervised the required socket process; and disabled remote SSH jobs unless operators attest external per-job isolation. Updated deployment artifacts and security evidence together.
- [2026-07-21] [Fix] Fixed the scheduling worker's repeating `dispatch loop error: Invalid time value` on legacy schedules. Lowercase persisted time units such as workflow `hours` are now normalized before interval conversion; unknown units and all non-finite interval/date inputs resolve to an unschedulable `null` instead of `new Date(NaN)`. Workflow spec conversion moved into the pure, tested schedule-math module, with regressions for legacy event/workflow units and invalid dates. Worker heartbeats now follow a successful dispatch tick so a broken dispatcher cannot advertise healthy scheduling, and worker container probes consume successful health responses instead of timing out on keep-alive connections.
- [2026-07-21] [Security] Conducted full security audit (auth, crypto, injection, web, dependencies); findings in `_plans/security-audit/audit.md`.
- [2026-07-21] [Security] Fixed SSRF in HTTP_REQUEST event executor: outbound requests now reject internal/metadata/RFC1918 targets via a DNS-guarded agent (validates resolved IP at connect time, defeating rebinding), no longer follow redirects, and cap response/request size (`src/lib/ssrf-guard.ts`, `src/lib/scheduler/http-executor.ts`).
- [2026-07-21] [Security] Locked down the `toolActionLogs` tRPC router: `getRecent`/`getByEventId`/`getStats` were `publicProcedure` and leaked all users' tool-action logs; now `protectedProcedure` scoped to the caller's own events.
- [2026-07-21] [Security] API tokens are now stored as a one-way SHA-256 hash instead of reversible ciphertext, looked up with a single indexed query (was O(n) decrypt-all-per-request). Legacy encrypted tokens are migrated to a hash on first use, so existing tokens keep working (`src/lib/api-token-hash.ts`, `src/server/storage.ts`).
- [2026-07-21] [Security] Added per-IP rate limiting to all authentication endpoints — tRPC `userAuth` login/register/reset/activate/verify procedures and the NextAuth credentials `authorize` path — to block brute force, token guessing, and registration/email spam.
