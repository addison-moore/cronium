- [2026-11-09] [Fix] **The Save button on a workflow's Canvas tab now saves what the canvas shows, and is on exactly when that differs from what's saved.** The canvas told the page about a change only when a connection changed, so a node dropped, moved or deleted on its own never reached the save. With a node dropped on a workflow of two, Save sent the two, said "Workflow saved successfully", and a reload showed the two. A moved node went back to where it was, and a workflow created on the new-workflow page with one dropped node was stored with none. Opening the canvas turned Save on with nothing changed. Any read of the workflow turned it off again with edits still on the canvas, and every refocus brings one, because superjson's new dates make each answer new to React Query: after deleting a node and switching windows, Save was off, the Overview tab showed the deleted node again, and so did the canvas once reopened. Now every change to what a save writes counts, a dragged node once it's let go, and an undo that brings the canvas back to what's saved turns Save off again. A read keeps edits that aren't saved, and the read after a save, which brings every node back with a new id, isn't a change. "Undo all changes" goes back to the last save, where it used to keep a node dropped after one.
