# 2026-11-09

- [2026-11-09] [Security] **An Email credential with Enable TLS ticked no longer signs in or sends without TLS.** Nothing read the box, which is ticked by default. A send and Test connection used STARTTLS only when the server listed it, so a server without TLS got the SMTP password and the whole message in plaintext, and so did anyone between Cronium and the server who removed STARTTLS from that list. Measured against Mailpit: a relay that removed `250-STARTTLS` from the answer of a server offering TLS read `AUTH PLAIN` with the password, and the message, from both. A ticked box now asks for STARTTLS whether or not it's listed, and ends the session before signing in if the server refuses it or the upgrade fails. Through the same relay, the session switched to TLS and the email arrived. Enable SSL, which is TLS from the first byte on port 465, is unchanged, and with it ticked the TLS box has nothing to add. Unticked, Enable TLS works as it did: STARTTLS when the server offers it, plaintext when it doesn't. **Upgrade:** a credential pointed at a server without STARTTLS, such as a local relay on port 25 or a mail catcher like Mailpit or MailHog, now fails every send and Test connection with `<host> didn't switch to TLS when asked (STARTTLS), so Cronium didn't sign in or send anything. To use this server without encryption, untick Enable TLS on this credential.`, followed by what the server answered, and a run's output starts `The mail server didn't switch to TLS`. To find such credentials before a run fails, press Test on each Email credential on the Tools page. Untick Enable TLS on any that should go on sending unencrypted.
