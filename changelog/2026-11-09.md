# 2026-11-09

- [2026-11-09] [Security] **One signed-in user can no longer open thousands of connections at once to hosts they typed, or use Cronium as a fast port scanner.** Testing, adding or re-keying a server, a server's health check, alone or through `servers.bulkOperation`, `POST /api/servers`, `PUT /api/servers/[id]`, and testing a tool through `tools.testConnection` or `tools.testCredentials` each connect to wherever the user typed, and nothing limited them. `withRateLimit` reads then writes, so it doesn't stop calls made at the same moment. Measured through the real routes with real Postgres and Valkey: 5,000 `servers.testConnection` calls at once at a server that never answers held 5,000 sockets for `ssh2`'s 60 seconds, and with a limit of 1,024 open files about 3,900 of them failed with `EMFILE`. One user calling in 8 loops reached a closed port 269,563 times in a minute, and each answer says whether something listens there. Each user now gets 8 of these at once in each app process. Up to 64 more wait their turn, in order, for up to 15 seconds, and past that a call is refused at once. At most 60 start a minute for each user, counted atomically in Valkey, so calls made at the same moment can't get past it, and every app process shares the count. A refusal is a `TOO_MANY_REQUESTS` error, or a 429 from the REST routes with `Retry-After` for the minute, that says which limit was reached. It comes before anything connects or is written, so it can't mark a server offline, and the Tools page shows a refused tool as not checked, with the reason in its tooltip, rather than broken. Its badges also show that a check is under way. **When Valkey doesn't answer** within 2 seconds, each process counts by itself, says so once in the log, and asks Valkey again 10 seconds later, rather than refusing every server and tool check as sign-in does. With more than one app process, a user can start 60 a minute in each while that lasts. **What changes:** opening the Tools page tests every tool it lists in one request, so a page of more than 8 tools at hosts that don't answer takes longer: 20 SQL tools whose server never answers took 20 seconds to show, where they took 10, and 4 of them showed as not checked. 20 that answer took under a tenth of a second either way. A user who reaches 60 in a minute, for example with many tools and the page opened several times, sees the rest as not checked until the minute is up. The count is in fixed windows, so a minute that spans two can see up to 120. A check that never finishes keeps its turn: every connection here has a time limit, but a server's health check commands don't once it's connected, so a server that answers keep-alives and never finishes a command keeps one of its owner's 8 turns until the app restarts.
