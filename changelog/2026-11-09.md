- [2026-11-09] [Security] **A server's health check now gets only that server's answers, and SSH health checks and connection tests close their connections.** The app's SSH service is one object for the whole process, and it kept each call's connection on itself, so calls at the same moment, whoever made them, ran over and closed each other's connections. A health check that overlapped another could come back with the other server's kernel release, CPU count, memory and uptime, which a server's page shows, and the other check then failed. One that overlapped a connection test, which anyone signed in can run against any address, failed with `Cannot read properties of undefined (reading 'exec')`, and the server was marked offline. Each of those left a connection open on the server, kept alive with nothing to close it, and so did a health check whose command the server refused, or that overlapped a connection test that failed. Each call now has its own connection and closes it however it ends, and the messages are the same. Nothing else crossed over: each connection still signs in with its own server's credentials and checks its own host key, and a health check only runs its five fixed commands.
- [2026-11-09] [Security] **An SSH health check now gives up on a server that doesn't answer, and closing an SSH connection always closes its socket.** A health check waited with no limit for each of its five commands, so a server that took a command and never answered held `servers.checkHealth`, or a bulk health check, and its SSH connection for as long as the app ran, and anyone signed in can point a server at a host they control and check it again and again. The five commands now get 30 seconds together, after which the check closes its connection and reports the server offline with `Health check timed out: <address> didn't answer its commands within 30 seconds.` Closing a connection also said goodbye and then waited for the server to close its side, so a server that never did kept the socket open for good, after a health check, a connection test or a refused password alike. The socket now closes 5 seconds later if the server hasn't closed it. Every other message is the same.
