# Changelog - 2026-07-16

- [2026-07-16] [Bug Fix] Workflow conditional branching now actually works — prerequisite for removing conditional actions (`_plans/conditional-actions/`). Three fixes, all of which affect **workflows** regardless of that decision. (1) **Edge conditions could not be changed in the builder.** The edge's condition was written under two names: the load/save transforms and the API contract (`workflowEdgeSchema.data` = `{ connectionType }`) use `connectionType`, but `WorkflowCanvas.onConnect` created edges with `data.type` and normalized existing edges to carry both — and `ConnectionEdge` read `data.type ?? data.connectionType`, so `type` **shadowed** the real value. Once any edge was added, picking "On Failure" on another edge left the badge reading "Always" until a save+reload (the value persisted correctly; the UI lied). Standardised on `connectionType` and removed `data.type` everywhere (`ConnectionEdge.tsx`, `WorkflowCanvas.tsx` ×6 sites, `workflows/new/page.tsx`, `WorkflowDetailsForm.tsx`) — it was also confusable with React Flow's own `edge.type` (`"connectionEdge"`). (2) **`cronium.setCondition()` never reached the job.** `executions/[executionId]/condition/route.ts` did `eq(jobs.id, executionId)`, but `executionId` is `exec_<jobID>_<ts>` — it never equals a job id, so the UPDATE matched **zero rows** and returned 200 anyway. Now keys on `execution.jobId` (already resolved 17 lines above), and the read-modify-write of the JSONB column runs under a row lock like the sibling `/output` route, so `setCondition()` and `output()` can no longer clobber each other. (3) **The condition was dropped at completion.** `updateJobStatus` replaces `job.result` wholesale, and the update route only carried the existing result forward when an `output` was present — so a script calling `setCondition()` without `output()` lost its condition. Extracted the merge to a pure, tested `lib/unified-io/merge-completion-result.ts` (mirroring `resolve-input.ts`) that always carries the runtime's result forward, promotes `output` → `scriptOutput`, and preserves `exitCode`. Together these make workflow `ON_CONDITION` edges functional for the first time. Verified: fix (2) confirmed live against the running dev stack (the condition now lands on the job row, pre-existing `exitCode`/`metrics` preserved; probe reverted); fix (3) covered by 8 new regression tests; typecheck + lint clean, 149 tests passing, production build generates all 49 routes.
