# 2026-07-26

- [2026-07-26] [Feature] Scripts can invoke tool actions again (FINDINGS #28/#1). New app route `POST /api/internal/tools/execute` is the counterpart the runtime relay always targeted but that never existed — so `cronium.toolAction()` and the `sendEmail`/`sendSlackMessage`/`sendDiscordMessage` wrappers previously 501'd. The route requires a new `tool:execute` per-job capability (added to `DEFAULT_JOB_CAPABILITIES`), binds it to the job (via the execution) and to the OWNER taken from the capability token — never the request body, so a script can't act as another tenant — resolves the caller's tool credential by TYPE (the SDK only knows the type, e.g. "slack"; the most recently created active connection wins when there are several — documented in the SDK READMEs), and executes through the SAME hardened engine the scheduler uses (`executeToolAction`): SSRF guarding, circuit breaker, rate limit/quota, secret redaction, and `tool_action_logs` auditing all apply — no second, weaker path. The runtime handler now decodes the script's `{tool, action, config}` and maps `config` onto the `params` field the route reads (closing the original #1 field mismatch where SDK config decoded to nil), relays with `X-Job-Capability`, and turns a ran-but-failed action into a 502 so the SDK rejects instead of returning a silent null. Shared wire fixture `tests/fixtures/internal-api/tools-execute.json` (consumed by both the Go relay test and the TS route contract test). Tests: 7 app-route contract tests (auth/scope/tenant/resolution/mapping) + Go handler relay tests (success, action-failure→502, params forwarding, capability carried) + the flipped backend pin. SDK READMEs updated; the 501 path removed.

- [2026-07-26] [Chore] Removed the vestigial orchestrator WebSocket log-shipping channel (FINDINGS #34). Nothing consumed its protocol — the client shipped flat-JSON raw-WS frames while the app's socket server speaks only Socket.IO (+ HTTP `POST /broadcast/*`), and live log lines actually reach browsers via `/broadcast/log-line`; the channel already defaulted off. Deleted `apps/orchestrator/internal/logger/{streamer,websocket}.go` and their tests, the `logStream`/`jobLogSink` daemon-core wiring and the streamer construction in the orchestrator entrypoint (the `cappedCapture` job-output path is unrelated and intact), the `WSLogConfig`/`LoggingConfig.WebSocket`/`APIConfig.WSEndpoint` config surface, and the `CRONIUM_API_WS_ENDPOINT` / `CRONIUM_LOGGING_WEBSOCKET_*` / `CRONIUM_WS_URL` env vars from all composes, the orchestrator env-var docs, and the env audit. `gorilla/websocket` is no longer a dependency of the orchestrator module (`go mod tidy`). The plain logrus bootstrap (`logger.New`/`Configure`) is unrelated and was kept. `docs/Execution_Flow.md` corrected to describe the real log path (output delivered with job completion; live lines via the app socket server), and its architecture diagram no longer shows an orchestrator→WebSocket arrow. Orchestrator Go coverage baseline lowered 36.08 → 32.8 — a legitimate denominator change from deleting a ~93%-covered package, not a coverage regression.
