# 2026-11-04

- [2026-11-04] [Security] Dependency sweep. `pnpm audit` was reporting 103 advisories (9 critical, 39 high), including five unauthenticated RCEs in `next@16.3.0`, two JavaScript-injection CVEs in `handlebars`, and an SSRF in the Next image optimizer; it now reports one low with no published fix (`deepmerge`). Upgraded every npm package to latest except ESLint 10 (`eslint-plugin-import` has no ESLint 10 support yet) and TypeScript 7 (`typescript-eslint` and `ts-jest` cap below it), which went to 6.0.3 instead. Notable majors: `next` 16.4.5, `nodemailer` 10, `@anthropic-ai/sdk` 1, `@hookform/resolvers` 7, `dotenv` 18, `tsup` 9. Raised and re-documented the `pnpm-workspace.yaml` security overrides. Removed the stale `minimumReleaseAgeExclude` list.
- [2026-11-04] [Security] Go: `golang.org/x/crypto` v0.54 → v0.58 fixes two SSH denial-of-service advisories reachable from the orchestrator's pool (GO-2026-6354, GO-2026-6355). Go toolchain 1.25.12 (out of support) → 1.27.3 in `go.work`, CI, and the Docker builders. Bumped all direct Go dependencies, plus `golangci-lint` 2.15.0 and `govulncheck` 1.9.0 in CI (the old `govulncheck` cannot read Go 1.27 export data).
- [2026-11-04] [Security] `aiohttp` 3.14.3 → 3.14.5 in the Python runtime image (parser, cookie, multipart, and connector advisories).
- [2026-11-04] [Fix] Orchestrator no longer pins Docker API 1.41. Stock Linux Docker Engine 29+ refuses anything below API 1.44, which would fail every container job with a 400 at `ContainerCreate`. The API version is now negotiated with the daemon unless an operator sets `container.docker.version`.
- [2026-11-04] [Chore] Next config: removed the `eslint` key Next 16 rejects, and `images.dangerouslyAllowSVG` (every SVG is a same-origin static asset, which `next/image` serves directly when the flag is off, so nothing changes visually but the optimizer stops parsing SVG). Externalized `nodemailer` for the client webpack build. Dockerfile pnpm 11.14.0 → 11.20.0 to match `packageManager`.
- [2026-11-04] [Fix] **Saving an event no longer corrupts its environment variables.** Since the vault migration, the event read path returned env var ciphertext: the edit form displayed `crn.1...`, and any save encrypted that ciphertext again, so the script received an envelope instead of its secret (and a further layer per save). Owners now read plaintext; existing corrupted rows heal on read and at delivery because `decryptEnvVarValue` unwraps nested envelopes under the same binding; `createEnvVar` leaves a value that is already ciphertext for its binding alone. Forks re-encrypt under their own binding. Forks made while the bug was live hold an envelope bound to the source event, which cannot be recovered automatically: re-enter those values. Tokens scoped below `full` (such as `mcp`) get keys only.
- [2026-11-04] [Security] Closed an SSRF bypass: `http://[::ffff:169.254.169.254]/` reached cloud metadata from an HTTP_REQUEST event or webhook. URL parsing serializes IPv4-mapped addresses in hex, which the guard's dotted-tail regex never matched, and Node skips DNS for IP literals so the connect-time check never saw them. `isDisallowedIp` now parses IPv6 numerically and judges every form that embeds IPv4 (mapped, compatible, translated, NAT64, 6to4) by the IPv4 rules, and also blocks Teredo, site-local, multicast, and discard.
- [2026-11-04] [Fix] HTTP_REQUEST events and outbound webhooks to a hostname work again. The SSRF-guarded DNS lookup ignored `options.all`, so on Node 20+ (where `autoSelectFamily` is on) every connection failed with `ERR_INVALID_IP_ADDRESS`. It also now checks every resolved address rather than only the ones matching the requested family.
- [2026-11-04] [Security] The HTTP executor no longer logs the whole `AxiosError`, which wrote each event's request headers (including `Authorization`) to the server logs, or the request URL.
- [2026-11-04] [Security] Tokens can no longer exceed their scope on REST. `authenticateRestPrincipal` only enforced scope when a route declared a path, so `/api/admin/*`, `/api/logs*`, and the remote-command terminal route accepted any token, including `mcp`-scoped and legacy deny-all ones. A route with no declared path now requires `full`.
- [2026-11-04] [Security] `X-Real-IP` is honored only behind `TRUSTED_PROXY_HOPS`. It was treated as the socket peer, so a client could take a fresh login rate-limit bucket per guess (defeating brute-force protection) and claim an allowed address on a webhook IP allowlist. **Deployments behind a proxy must set `TRUSTED_PROXY_HOPS` for per-client rate limits and webhook IP allowlists to work.**
- [2026-11-04] [Security] Closed post-login open redirects: `/auth/signin?callbackUrl=https://evil.example` (the form followed it unchecked), and the NextAuth callback's prefix match, which allowed `https://app.example.evil.com` and `//evil.com`.
- [2026-11-04] [Security] Revoked sessions now stop everywhere. `/api/socket-ticket` (which opens terminals), tool OAuth, and MCP consent checked only that the JWT was valid, not its `sessionVersion`. MCP OAuth access and refresh tokens now carry the version, so a password reset or "revoke sessions" actually ends them; refresh tokens otherwise rotated for 30 days regardless. `revokeUserSessions` also revokes the user's API tokens, as its description always said. **MCP clients must re-authorize once after this upgrade.**
- [2026-11-04] [Security] MCP OAuth rejects scopes it does not offer. `scope=full` used to be stored as requested behind a consent page describing `mcp`, and a consent ticket was not bound to its scope. Deny-all API tokens can no longer approve a grant.
- [2026-11-04] [Security] Admin mutations no longer return raw user rows (password hash, MFA secret, recovery-code hashes, invite token) to the browser: `inviteUser`, `updateUser`, `toggleUserStatus`, `approveUser`, `denyUser`, `enableUser`, `disableUser`, and `promoteUser` all use the secret-free DTO the read paths already used.
- [2026-11-04] [Security] `getCurrentUser`, `updateProfile`, and `deleteAccount` resolve the account by session id. They looked it up by the email frozen in the JWT, so after an email change, a stale session could read, edit, or delete whoever registered the old address next.
- [2026-11-04] [Security] An admin can no longer demote or disable themselves through `admin.updateUser`, and the last active admin cannot delete their account; either could leave an instance with no administrator.
- [2026-11-04] [Security] TOTP codes are single-use (RFC 6238 §5.2), and recovery-code consumption is an atomic database update, so concurrent uses cannot restore each other's code. MFA mutations are rate-limited per account.
- [2026-11-04] [Security] Invite tokens are stored hashed, like reset tokens. Invitations pending at upgrade stop working: resend them. `forgotPassword` no longer waits for the mail server, which revealed registered addresses by response time. An unrecognized bearer token no longer loads every active token row.
- [2026-11-04] [Fix] Bearer tokens work on `/api/events` and `/api/logs`. `proxy.ts` redirected any request without a session cookie to the HTML sign-in page before the handler ran.
- [2026-11-04] [Security] Webhook delivery records no longer store decrypted custom headers. `webhook_deliveries.headers` kept each request's headers in plaintext, including credentials like `Authorization`, and the history API returned them, undoing the encryption those headers get at rest. New records keep only the system headers and the custom header names; migration `0012` scrubs existing rows.
- [2026-11-04] [Security] Webhook hardening: a request stamped at the future edge of the timestamp window could be replayed once the delivery id expired (it is now remembered for the full 10 minutes); unexpected errors no longer return `error.message` to unauthenticated callers; retry settings are bounded so `maxRetries: 1e9` cannot turn a webhook into a loop against an external host; the inbound key is no longer forwarded to outbound subscribers; the workflow webhook rate limiter keys on the key's hash instead of writing the raw credential into Valkey.
- [2026-11-04] [Fix] Webhook payloads keep their shape. `sanitizePayload` turned every array into an object with numeric keys in everything a webhook stored or forwarded, and a JSON `__proto__` key replaced the result's prototype. An array body now goes under `data` instead of spreading into numeric keys.
- [2026-11-04] [Chore] `WebhookQueue` reduced to what is used. Removed the in-memory dead-letter queue (nothing read it, and it kept decrypted secrets and headers in memory forever), the `pause()` that did nothing, and unobserved events. Removed `WebhookManager.cleanup()`, which nothing called and which compared timestamps with `eq`, so it could never have deleted anything.
- [2026-11-04] [Security] **Execution logs are owner-only.** `getFilteredLogs` and `logs.getWorkflowLogs` returned the output and errors of any other user's shared event or workflow, to any account including Viewers, while `events.getLogs` and `logs.getById` already refused the same data on the stated rule that sharing does not grant access to execution history. The logs page's "Shared" filter now returns nothing; its removal is a product decision left open.
- [2026-11-04] [Security] Removed `/api/admin/terminal`. No client called it (the web terminal uses the socket server), and it ran arbitrary commands on remote servers over a separate SSH stack with no host-key verification and no CSRF guard, plus on the Cronium host itself behind a flag. Its `CRONIUM_ALLOW_LOCAL_HOST_TERMINAL` flag and the `lib/ssh/terminal.ts` + `lib/ssh/shared.ts` stack went with it.
- [2026-11-04] [Security] `POST /api/events` no longer logs the request body, which wrote env var values and HTTP headers to the server logs.
- [2026-11-04] [Fix] `POST /api/events` works without `startTime` and `serverId` (under Zod 4 they had quietly become required keys), stores the `description`, `shared`, and `tags` it validates, and stores HTTP headers as an array instead of a JSON string the executor then ignored. A schedule set over REST now runs: it sets `triggerType` (which stayed `MANUAL`, so the event never fired) and materializes `next_run_at`. `PATCH /api/events/:id` re-materializes too, so pausing over REST stops the event. Access failures say "Access denied" rather than "Internal server error" with a 403.
- [2026-11-04] [Fix] `PUT /api/servers/:id` with a blank `sshKey` keeps the stored key, as its schema comment always said. It overwrote it with an empty string. `/api/logs` clamps `pageSize` to 100 and rejects non-numeric ids.
- [2026-11-04] [Fix] Changing a server's address or port clears its pinned SSH host key. Otherwise the server failed host-key verification forever, with nothing able to clear it.
- [2026-11-04] [Fix] Archiving a server no longer locks its owner out of the events bound to it: they can open and repoint them, and only running them is refused.
- [2026-11-04] [Fix] One job that cannot be prepared no longer takes down the claimed batch. An env var that stopped decrypting after a key change made `/jobs/claim` return 500, leaving every job in the batch stuck until its lease expired, after which they were failed or re-run. That job now fails on its own with a clear message.
- [2026-11-04] [Fix] Removed `withTransaction` from `events.create`, `update`, and `fork`. It opened a transaction nothing used (storage writes through the global pool), so nothing was atomic, and each call held a pool connection while waiting for a second one: the same self-deadlock fixed for workflows in August. Events are now scheduled after their env vars and servers are written, so the dispatcher cannot run one half-configured.
- [2026-11-04] [Fix] `setUserVariable` is an atomic upsert (two steps setting the same new variable raced into a unique-constraint failure). `events.fork` keeps the owner's `toolActionConfig` and `triggerType`. `getEventWithRelations` no longer falls back to returning an event with empty env vars and servers on a query error, which could dispatch a job without its configuration. `admin.getSystemStats` counts every event, not just the first admin's. `jobs.list` accepts `TIMED_OUT`. MCP handles `null` batch members and caps batches at 25. A log no longer stays PENDING forever when creating its job fails. The output size limit is measured in bytes.
- [2026-11-04] [Chore] Removed `/api/callback`, `/api/login`, and `/api/logout`, which each redirected to themselves forever (left over from an Express server that no longer exists).
- [2026-11-04] [Fix] Long-running jobs keep their tokens. SSH jobs got a fixed 1-hour runtime token, the runtime rejected any token older than 2 hours, and completion tokens were clamped to 6 hours, regardless of the job's timeout. So a job running past those limits lost `cronium.output()` partway through, and past 6 hours its completion report was refused, after which the sweeper failed or re-ran a job that had already finished. Tokens now last for the job's timeout plus a buffer, with a 7-day ceiling; they are still revoked as soon as the job ends.
- [2026-11-04] [Fix] SSH reverse tunnels no longer share port 9090. A second concurrent job on a server, or anything else on that port (often Prometheus), silently fell back to bundled mode and lost the runtime API. `sshd` now picks a free port per job. SSH jobs also honor `CRONIUM_MAX_EXECUTION_TIMEOUT`, as the docs already said.
- [2026-11-04] [Fix] Live container log lines stay whole. Each `Read` was split on newlines, so any line straddling a read boundary arrived in two pieces (multi-byte characters included), and every live line carried a Docker timestamp prefix the stored output did not have.
- [2026-11-04] [Security] The runtime API caps request bodies, so one job cannot exhaust a shared runtime's memory, rejects tokens with no expiry instead of panicking on them, and no longer applies `chi`'s deprecated `RealIP` (spoofable, and nothing behind it needed it). The multi-server SSH executor no longer holds a context per update until the job ends.
- [2026-11-04] [Chore] Removed dead Go code flagged by staticcheck: the SSH `phase_executor.go` (a parallel execution path nothing called), container `log_collector.go`, unused stream helpers, and the runtime's `GenerateToken`/`RefreshToken` (there is no refresh route), with their config fields.
- [2026-11-04] [Test] The runtime's auth and rate-limit middleware now have tests (they had none), and the Go coverage baselines are raised to match: orchestrator 35.49%, runtime 50%.
- [2026-11-04] [Security] Workflow input can no longer rewrite a tool action. It was merged over the configured parameters, so anyone holding a workflow's webhook key could replace a SQL statement or an email's recipients, and an upstream step's `text` or `body` output silently overwrote the same-named field on the next action. Input also shadowed user variables, which let a webhook caller repoint `{{cronium.getVariables.apiBase}}` at their own host and collect the Authorization header sent with it. Workflow data now reaches a parameter only where its template says `{{cronium.input.*}}`.
- [2026-11-04] [Fix] Template values arrive intact. Everything was HTML-escaped regardless of where it was going, so `Bearer abc==` became `Bearer abc&#x3D;&#x3D;`, query strings gained `&amp;`, and JSON bodies gained `&quot;`. Values are now encoded for their destination: verbatim for URLs, headers and bound parameters, valid JSON for JSON documents (a value cannot add fields), escaped HTML for HTML email bodies, and only `&`, `<` and `>` for Slack and Teams messages. Plain-text email bodies are now escaped for their HTML alternative, which they were not.
- [2026-11-04] [Fix] Objects and arrays render as JSON in templates. The documented `{{cronium.input.rows}}` was reaching its destination as `[object Object],[object Object]`.
- [2026-11-04] [Fix] A template that fails to compile now fails the job. Its error text was being sent on as the message.
- [2026-11-04] [Security] Signup goes through the validated, rate-limited route. The form used a separate server action, callable by anyone, with no rate limit, no password policy and no input validation, and it spent a bcrypt hash before checking anything. The action is gone.
- [2026-11-04] [Security] The password-check step of login no longer returns the user record. Any non-empty `totp` got past its MFA gate, so someone holding only the password could read the profile. It now returns only whether to proceed, and `lastLogin` is recorded when NextAuth creates the session. `userAuth.register` likewise returns only the new account's status.
