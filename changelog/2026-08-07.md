# 2026-08-07

- [2026-08-07] [Chore] Upgraded to **Next.js 16.3.0** (from 15.5.21) across `cronium-app`, `cronium-info`, and `packages/ui`, plus `@next/bundle-analyzer`, `eslint-config-next`, and `@next/eslint-plugin-next`; a single `next@16.3.0` resolves workspace-wide and `pnpm audit --audit-level high` still exits 0. Plan and pre-upgrade compatibility audit: `_plans/nextjs-16/PLAN.md`. Most of Next 16's breaking changes were already satisfied (async request APIs were migrated during the 15 upgrade — `params` is typed `Promise<>` and awaited, no bare `cookies()`/`headers()`; Node 22 ≥ the new 20.9 floor; React 19.2.8; next-auth 4.24.15 already declares `^16`; no AMP, `serverRuntimeConfig`, `next/legacy/image`, `images.domains`, parallel routes, `revalidateTag`, or `experimental_ppr`/`dynamicIO`/`useCache` usage). Three things did need work. **(1) Bundler:** Turbopack is now the default and `next build` hard-fails when a webpack config exists; `cronium-app`'s `next.config.mjs` carries server externals (ssh2/mysql2/mongodb/ioredis/`@anthropic-ai/sdk`) and client `resolve.fallback` stubs, and Turbopack would silently ignore both in dev too. Pinned `--webpack` on the app's `dev`/`build` scripts, its Dockerfile build, and the e2e harness build, deliberately keeping the bundler migration (→ `serverExternalPackages` + `turbopack.resolveAlias`) as a separate change; `cronium-info` has no webpack config and moves to Turbopack. **(2) `next lint` removed:** both apps already used flat config, so this was scripts (`eslint .`) plus adding `eslint` as a direct devDependency of `cronium-app` (previously only reachable through `next lint`) and switching `@cronium/eslint-config/next.js` to the plugin's native `configs.recommended` instead of bridging the legacy shape through FlatCompat — rule coverage verified unchanged via `--print-config` (22 `@next/next` + 84 `@typescript-eslint` rules still active). `eslint .` reaches four root files `next lint` never linted (`server.ts` 17 problems, `drizzle.config.ts` 1, and `tailwind.config.ts`/`instrumentation.ts` which aren't in the tsconfig project and can't be type-parsed); those are ignored with a comment so the gate is identical to pre-upgrade, and cleaning them up is tracked separately. **(3) `middleware` → `proxy`:** `src/middleware.ts` → `src/proxy.ts` with `middleware()` → `proxy()`. This is not just a rename — `proxy` always runs on the Node runtime (edge unsupported, not configurable) where it previously ran on edge, and the file carries the Phase-1.6 security headers, so it was verified against a production server: CSP with `strict-dynamic` and a **per-request** nonce (different on every request), that nonce still reaching Next's own preload `Link` header (request-header forwarding intact), HSTS/X-Frame-Options/nosniff/Referrer-Policy/Permissions-Policy applied, and unauthenticated `/dashboard` still 307ing to `/auth/signin` with headers on the redirect. A side effect is that the build's Edge Runtime `process.cwd` warnings are gone. Also dropped a now-unused `@ts-expect-error` in `Terminal-lazy.tsx` (Next 16 types CSS side-effect imports, so the directive became a TS2578 error). Verified: workspace typecheck + lint green, app suite 123 suites / 1,944 tests, security suite 33 suites / 239 tests, production builds of both apps, and the full e2e pipeline with a forced rebuild. Noted for follow-up: `src/app/middleware.ts` is dead code (middleware is only honored at the project root, so Next has never executed it) and references an Express auth server that no longer exists.
