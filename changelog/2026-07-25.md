# 2026-07-25

- [2026-07-25] [Security Fix] Tool-action failure path no longer leaks credentials into logs or job output (testing-plan FINDINGS #2). `tool-action-executor.ts` logged the parsed tool config unredacted at failure (`[ToolAction] Config at failure:`) and passed raw provider error text into result `stderr`, the console error/stack logs, the audit log, and `tool_action_logs.errorMessage` — provider errors can echo webhook URLs and tokens. Added a span-level `redactText` helper to `lib/tools/redact.ts` (masks JWTs, `Bearer` blobs, credential-bearing URLs — userinfo, secret query params, high-entropy path segments à la Slack webhooks — and standalone high-entropy tokens, without erasing the readable message the way all-or-nothing `redactSecrets` would) and applied it to every failure-path sink; the config log now goes through `redactSecrets` like the rest of the file. Regression tests: 7 new `redactText` unit cases plus an executor test proving a provider error echoing a webhook URL + token reaches stderr/DB with the credentials masked and the readable text intact.
