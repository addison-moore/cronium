# 2026-07-22

- [2026-07-22] [Security] Phase 2.1: shipped the key-rotation driver (`pnpm --filter @cronium/app rotate:secrets`). Made the tool-credential scheme keyring-aware (new `ENCRYPTION_KEYS_RETIRED` fallback, matching the vault), so a rotation re-encrypts every at-rest secret — servers, env vars, system settings, MFA secrets, user variables, webhook secrets/headers, tool credentials, and OAuth tokens — from a retired key onto the active key. Idempotent + resumable (re-run = interrupted-rotation recovery; swap keys to roll back), fails safe on authenticated-decrypt errors (never writes mis-bound ciphertext), and WARNS about legacy pre-vault values it can't rotate. Verified end-to-end with a live ORIGINAL→NEW→ORIGINAL round-trip against the dev DB (0 errors, fully restored) plus retired-key/interrupted-rotation unit tests. Runbook + `ENCRYPTION_KEYS_RETIRED` documented.
