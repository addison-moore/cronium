# Changelog - 2026-07-17

- [2026-07-17] [Refactor] Removed the Conditional Actions feature (see `_plans/conditional-actions/`). Workflows already cover the same branching — on-success / on-failure / on-condition edges, fan-out, scheduling, and both "run another event" and "send a notification" — and the two features silently compounded (an event used as a workflow step fired its own conditional actions in addition to the workflow's edges). With no users and no production data, the whole feature was removed rather than deprecated. Dropped: the `ConditionalActionsSection.tsx` form, the `conditional_actions` table + `ConditionalActionType` enum + relations, the storage methods, the single execution dispatch site (`event-handlers.ts` and the hook in `job-service.updateJobStatus`), the CA blocks from the events tRPC router and both REST routes, `event-validation.ts` (the CA-only cycle guard), and the `isSendMessageAction`/`conditionalActionConfig` metadata from the Slack/Discord/Email plugins (those send actions keep working as tool-action events and as workflow steps). Also removed ~1,500 lines of now-dead code the feature had accreted (`status-badge-renderer.tsx`, the isolated `useEventForm`/`types`/`guards` cluster). Deleting the feature also erased a large latent-bug surface, including one action type (`ON_CONDITION`) that had never worked and a `deleteActionsByEventId` bug that duplicated rows and destroyed other events' actions on every edit. The `conditional_actions` table was dropped from the dev DB (the app applies schema via `db:push`, not migrations). Docs updated across the app docs and the `cronium-info` site (the `/docs/conditional-actions` page and its nav/sitemap/index links removed; guidance repointed at Workflows). Net: ~3,800 lines removed, one table dropped, two overlapping branching systems collapsed into one. Verified: typecheck + full-app lint clean, 154 tests passing, both app and info-site production builds compile, and the `conditional_actions` FK to `events` is confirmed gone in the dev DB.
- [2026-07-17] [Feature] MongoDB tool: new `mongodb` tool plugin (`src/tools/plugins/mongodb/`) mirroring the SQL tool's design. Five actions — Find Documents and Aggregate Documents (reads; results flow to the next workflow step via Unified I/O, streamed with the same fail-don't-truncate row/byte guards as SQL, `$out`/`$merge` rejected in pipelines) plus Insert/Update/Delete Documents (explicit writes; mass update/delete with an empty filter is refused, delete always requires a filter). Structured credentials (standard or `mongodb+srv`/Atlas scheme, host, port, database, user, password, auth source, TLS mode) with the `mongodb` driver imported dynamically and one short-lived connection per call; Extended JSON (`$oid`, `$date`) supported in filters/documents; BSON values (ObjectId, Decimal128, Long, Binary, dates) normalized to JSON-safe output. Registered in the server manifest registry and client plugin registry. Tests: 43 unit tests (helpers + all five actions with a mocked client) plus a gated live-integration suite (`CRONIUM_MONGO_TEST_URL`) verified against MongoDB 7 in Docker. Docs site tool list updated.
