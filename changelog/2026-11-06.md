- [2026-11-06] [Security] **`rotate:secrets --encrypt-legacy` now covers the rest of the columns that can hold old values:** server SSH keys and passwords, event env vars, MFA secrets, sensitive system settings, tool credentials and OAuth tokens. The first four can hold static-AAD ciphertext from before the vault, which isn't bound to its row and which a key change orphans, or plaintext, and nothing moved a row nobody saved again. The last two could hold plaintext, which `rotate:secrets` skipped without counting. The vault columns end up under the same bindings the app writes, tool credentials and tokens in the format their read paths already use, and the worker's boot warning counts all of them. Because the read path only guesses from a value's shape, the run goes by what authenticates: older ciphertext has to pass its GCM tag under a key in the ring, which also rescues a value under a retired key that the app couldn't read at all, and a value with that shape that nothing opens is named and left alone, because it can be plaintext or ciphertext under a lost key. A value whose reads already return ciphertext, as one of 1 to 4 bytes or one encrypted twice by the old edit form does, is encrypted as it reads and named with a `NOTE:`, so no script changes behaviour because of this run. Run it before changing `ENCRYPTION_KEY`. It's run by an operator: see `docs/ENVIRONMENT_VARIABLES.md`, which also lists the wider `VACUUM FULL` the old values need. `tests/storage/legacy-secrets-fields.test.ts` covers this against real Postgres.
- [2026-11-06] [Security] **Key rotation no longer overwrites a value changed while it runs.** Every write in `rotateAllSecrets` matched on id alone, so a webhook secret regenerated, an OAuth token refreshed or an env var saved between its read and its write got the old value back, on all eight surfaces. Each write now requires the row version it read. A row that moved on counts as `changed-during-run`, neither re-encrypted nor an error, the CLI says to run it again and exits 1, and a later run finishes it. A failed write on webhooks or OAuth tokens no longer aborts the run, and a row error no longer logs the error's own message, which could quote part of a plaintext value. `tests/storage/secret-rotation-race.test.ts` covers this against real Postgres.
