- [2026-11-06] [Fix] **Every action in the events list now says when it fails.** Run, Duplicate and changing an event's status (Active, Paused, Draft, Archive, Unarchive) showed nothing at all when the server refused, so the click looked ignored. Each now shows a toast with the server's reason, such as "A previous run of this event is still active (overlap policy: SKIP)". For a validation failure that's the sentence, not the Zod issues as JSON. A bulk action now gives one toast with the reason, in place of a bare "1 failed", and changes only the rows that worked: bulk activate and pause used to mark refused events as changed, and bulk archive and delete took them off the list while they were still there. When nothing worked it's an error, not "Partial Success … 0 of 2". A bulk action that works also gives one toast now, not one per event plus the summary. Bulk download gives the server's reason, and when an event selected for it is gone it says "Downloaded 1 of 2", where it used to claim both were in the file. `events.download` now returns `eventCount` for this. A failed single delete no longer also throws an unhandled rejection. Duplicate still can't copy a tool action or an event linked through `event_servers`, but it now says so.
- [2026-11-06] [Fix] **Duplicate works on events with servers, and a server's page lists its events.** Duplicate sent an event's server links under a name `events.create` ignores, so it couldn't copy a `REMOTE` event linked through `event_servers`, and it left out a tool action's config, so it couldn't copy those either. It now sends both. **An archived server stops a copy, as it does a fork:** no draft is made. A new copy or fork also appears in the list without a reload. `servers.getEvents` failed on every call against real Postgres, `column events.event_id does not exist`, and the server's page showed that as "No events configured to run on this server yet." It now lists them. On that page, Duplicate copies the links, the server column shows the event's servers, not `local`, and Fork really forks, where it used to run Duplicate on data with the owner's servers removed. The events list also no longer marks every row as someone else's until the viewer has loaded: rows show no share icon and only View Details until the session answers, and a failed `getCurrentUser` no longer leaves them that way.
