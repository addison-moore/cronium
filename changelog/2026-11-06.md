# 2026-11-06

- [2026-11-06] [Fix] **A `bash` that a container job's script starts can now call the `cronium_*` helpers.** It inherited the functions but not the shell variables they read, so every call failed with `Error: Max retries exceeded` before making a request. They now read `CRONIUM_RUNTIME_API`, `CRONIUM_EXECUTION_TOKEN` and `CRONIUM_EXECUTION_ID` each time they run, and a script can use `MAX_RETRIES` and `RETRY_DELAY` itself, which used to break its helper calls. The bash runner image no longer sets `BASH_ENV`: it named a file the `/home` tmpfs hides, so it did nothing in a job. **Upgrade:** rebuild `cronium/runner:bash-alpine`. A script that unsets `CRONIUM_RUNTIME_API` or `CRONIUM_EXECUTION_ID` can no longer call helpers, and changing `CRONIUM_API` or `CRONIUM_EXEC_ID` no longer redirects them.
- [2026-11-06] [Fix] **The key rotation driver now hashes API tokens from before tokens were hashed,** so nobody has to use or replace one before the key changes. An unused token used to get a 401 for good once the old key went, because the lookup that hashes a token on use only tries the active key. A real run now opens each active, unexpired token under any key in the ring and stores its hash, unless the row has changed since it read it, and a dry run counts them as `hashed`. A token no key in the ring opens stays `legacy`, by name, with advice to add its key back or issue a new one. Each one still gets a 401 between the restart that changes the key and the driver's first pass, and running the driver on the current key beforehand avoids that. A row's failure line no longer includes Drizzle's message, which repeats every bound value.
