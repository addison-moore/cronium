- [2026-11-06] [Fix] **A script event set to `REMOTE` with no servers no longer runs in a local container.** It used to run on the Cronium host with only a console warning. Now it doesn't run: a scheduled run pauses the event and records a `NO_SERVERS` schedule incident, once rather than on every tick, a manual run gets the reason as a 409 (`CONFLICT` over tRPC), and a workflow step fails with the reason. Pausing alone wouldn't stop that step, because workflow steps don't check an event's status. `events.activate`, `events.update` and the REST create and edit routes refuse to set one up, as `events.create` already did. An edit that leaves where the event runs alone still goes through. HTTP requests and tool actions run in the worker wherever they're set to run, so they keep running. The event details page now shows why a run or an activation was refused, and it and the events list show its owner that such an event has no servers, where the list said `local`. **Upgrade:** there's no migration, so an event already in this state stops at its next scheduled run, and its incident says why. Choose a server or set it to run locally, then reactivate it.
- [2026-11-06] [Fix] **Deleting a server no longer starts its events running somewhere else.** That goes for every way to delete one, including the 30-day cleanup when `SERVER_CLEANUP_ENABLED=true`, which could start a job the app had refused for a month while the server was archived. An active `REMOTE` script event with no other server now pauses and stays `REMOTE`, with an incident naming the server. One linked through `event_servers` used to run in a container, and one with a direct server used to become `LOCAL`. A paused or draft event gets the incident and keeps its status. A `LOCAL_AND_REMOTE` event that loses its last server becomes `LOCAL` and keeps running, with an incident saying the remote half is gone. An event with a direct server and another linked one keeps the other, where it used to become `LOCAL`. An HTTP request or tool action with no other server becomes `LOCAL`, which changes nothing about its run. The delete dialog says all this in place of "Convert N events to local execution", and its list of active events now includes ones linked through `event_servers`.
