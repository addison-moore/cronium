# 2026-11-05

- [2026-11-05] [Fix] A workflow run that times out now writes its timeout line on its own workflow, under its owner. The sweep used the run's id as the workflow id, so run 2 of one user's workflow wrote `Workflow execution timed out` onto workflow 2, which could belong to another user, and the run's own workflow showed nothing. Where no workflow had that id, the insert failed its foreign key and the run's running jobs were never timed out here, which left them to the lease sweeper. A failed log write no longer affects the jobs, and finding them no longer loads the whole `jobs` table for each stuck run.
- [2026-11-05] [Fix] `POST /api/admin/cleanup` with `type: "workflow"` takes a run id, and its response now says so. It leaves a finished run alone, where it used to overwrite the result with `TIMEOUT` and add a timeout line, and it answers 404 when no run with that id is running, where it used to report success regardless. A failed update returns 500.
- [2026-11-05] [Fix] `POST /api/admin/cleanup` answers 400 to a request it can't read. A missing or zero `id`, an unknown `type`, an `id` with no `type`, or a body that isn't a JSON object used to fall through to the full sweep, which also times out every job older than 15 minutes, and `"id": true` timed out run 1. `{}` and `{"type":"all"}` still run the sweep. A cleanup that fails is now audited as `error`, where it left no audit line.
- [2026-11-05] [Fix] A timed-out workflow run records how long it really ran, in `total_duration` and its timeout line, and sets `updated_at`. It used to report the 30-minute limit, including for a run an admin stopped after two minutes or one stuck for hours. `total_duration` is capped at what its integer column holds, about 24.8 days, so a longer stuck run can still time out.
- [2026-11-05] [Fix] Migration `0014` moves timeout lines already on the wrong workflow to the run's own workflow and owner, on databases from the old `drizzle-kit push` flow as well. A line moves only when it can be tied to its run: no owner, the status, level and message only the old code wrote, and a timestamp equal to that run's `completed_at`. Two kinds stay where they are: a line whose run has since been deleted, and the first line of a run timed out twice through the admin route.
- [2026-11-05] [Test] A test now fails on a migration journal that is out of order. Drizzle skips an entry older than the last one a database applied, with no error, and two branches adding a migration at once can produce that.
- [2026-11-05] [Fix] A code editor that can't download Monaco no longer takes the page down. It used to throw to the route's error page, which lost unsaved form input and could only be cleared by a full reload. The form now stays up with the script in a plain text box, edits still reach the form, and the real editor takes over when a retry succeeds.
- [2026-11-05] [Fix] Bash scripts get syntax highlighting. `MonacoEditor` passed `bash` as the language, and Monaco's ID is `shell`, so they showed as plain text.
- [2026-11-05] [Fix] The code editor's expand and minimize buttons no longer submit the form around them. They had no `type`, so in the event form, clicking expand saved the event and left the page.
- [2026-11-05] [Security] An editor mounted without the app's Monaco setup now fails on our own origin instead of running Monaco from jsDelivr, and `worker-src` no longer allows `blob:`, which nothing has used since Monaco's workers became bundled chunks.
- [2026-11-05] [Chore] Stopped building a CSS language worker that no editor can ask for.
- [2026-11-05] [Test] The guard on direct `@monaco-editor/react` use now catches dynamic imports, `require` and re-exports as well as static imports, and the E2E suite fails if Monaco reaches the `commons` chunk or the server bundle.
- [2026-11-05] [Docs] `docs/DEPLOYMENT.md` now says building from source needs about 8GB. Its 4GB minimum applies to running the published images, and `next build` alone peaks above that.
