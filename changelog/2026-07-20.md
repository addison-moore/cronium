# Changelog - 2026-07-20

- [2026-07-20] [Fix] Added the scheduling worker to the local Docker development lifecycle: `pnpm dev:docker:up` now starts a healthchecked `cronium-worker-dev`, `dev:docker:down` stops it with the rest of the Compose project, and `dev:docker:build` builds its app-based worker image. The startup helper passes `env/.env.local` worker settings and translates loopback PostgreSQL hosts to `host.docker.internal`; development docs now distinguish the Docker worker from `pnpm dev:worker`.
- [2026-07-20] [Fix] Server console + status fixes (user-reported). **(1) Terminal teardown loop**: `useAuth` built the `user` object as a fresh literal every render; `Terminal.tsx` had that object in its main effect's dependency array, so every `setLoading` toggle re-ran the effect — disposing and recreating the xterm instance in a self-sustaining loop (flapping "Connecting..." badge, cursor alternating between default/text, keystrokes lost). `useAuth` now memoizes `user` on `userData`, and the terminal effect depends on `user?.id`. Verified live in Chrome against sandbox server 6: stable session, command executed. **(2)** `terminal-socket-manager` hardcoded `http://localhost:5002` while the other socket hooks honor `NEXT_PUBLIC_SOCKET_URL`; now aligned, with a same-origin fallback (`window.location` + socket port) so prebuilt images without baked `NEXT_PUBLIC_*` values still reach the right host. (The reported "Server not found for userId ..., serverId: 1" socket-server spam was a stale browser tab running pre-fix JS in the old retry loop with a session/server from a different DB state — the server correctly rejects it; close old Cronium tabs.) **(3) Server badge shows "offline" right after a successful save**: `servers.create` required a passing SSH test but never recorded it, leaving `online` NULL until a manual Check Status; create now persists `online: true` + `lastChecked`, and `servers.update` does the same when its credential-change connection test passes.
- [2026-07-20] [Feature] Scheduling overhaul Phase 1 — durable scheduling kernel (plan: `_plans/scheduling/PLAN.md`, findings: `_plans/scheduling/review.md`). **Schema**: events gain `timezone`, `scheduleKind`, `catchupPolicy`, `overlapPolicy`, `misfireGraceS`, `leaseLossPolicy`, `priority`; jobs gain `source`, `timeoutMs`, `maxAttempts`, `leaseExpiresAt`, `leaseLossPolicy`, `cancelRequested`, `activeKey`, `scheduledMiss` and `JobStatus.TIMED_OUT`; new `job_transitions` (status audit + transactional outbox) and `schedule_incidents` (missed/skipped/auto-paused records) tables; first indexes in the schema (claim, lease-sweep, dispatch, log/execution lookups) plus the `jobs_active_key_uq` partial unique index backing SKIP overlap policy (migration `0001_scheduling-kernel`, verified against a throwaway Postgres). **Kernel** (`src/lib/scheduling/`): `schedule-math.ts` — tz-aware, fixed-clock-tested next-run computation (true elapsed intervals, cron via cron-parser with DST handling, misfire grace, capped catch-up enumeration, cron validation, 10s interval floor; 22 tests); `job-transition.ts` — transactional CAS state machine with legal-edge enforcement, audit rows, and pg_notify (terminal states are absorbing: late reports can no longer un-cancel or overwrite); `outbox.ts` — SKIP LOCKED at-least-once consumer with poison-pill guard (worker hosts the loop in Phase 2); `dispatch.ts` — the single enqueue path replacing the three divergent copies in scheduler.executeScript/executeEvent and events.execute, which also revives the dead maxExecutions enforcement (auto-pause + incident) and lastRunAt bookkeeping. All job status writers (start/complete/fail/cancel/updateJobStatus/retry-requeue, the `/release` internal route — now CLAIMED-only — and the cleanup sweeper — now guarded TIMED_OUT instead of blind FAILED) route through the CAS kernel.
- [2026-07-20] [Feature] Scheduling overhaul Phase 2 — durable worker process (plan: `_plans/scheduling/PLAN.md`). **New `cronium-worker` service** (same app image, `worker.ts` entrypoint; dev: `pnpm dev:worker` — dev now runs three processes) hosting: the **schedule dispatcher** (SKIP LOCKED transaction over due `next_run_at` rows; misfire grace + SKIP/RUN_ONCE/RUN_ALL catch-up via pure `plan-ticks.ts`; QUEUE coalescing; CANCEL_PREVIOUS cancel-requests; advance-then-dispatch), the **in-process executor pool** (tool-action/HTTP jobs are now claimed with leases instead of fire-and-forget in the web process — crash-stranded QUEUED jobs are impossible), the **lease sweeper** (expired leases per `leaseLossPolicy` with retry backoff; unleased running jobs bounded by their own timeout instead of the old 15-min blanket; claim-stall recovery), **FK-safe retention** (30d default, logs detached not deleted), the outbox drain, workflow cleanup (`sweepJobs: false`), and a liveness heartbeat + `:5003` health endpoint. **Legacy scheduler removed**: `ScriptScheduler` is now a facade that materializes `events.next_run_at` (`materialize.ts`) — no node-schedule timers, no debounce heuristics; dead bootstrap routes `/api/startup`, `/api/cron`, `/api/init` deleted. **Health surfacing**: `/api/health` reports scheduler heartbeat; dashboard shows a persistent "scheduling is offline" banner when stale (PLAN §4.5). **Deployment sync**: worker service added to `docker-compose.example.yml` + `infra/docker/docker-compose.yml` with healthchecks; Dockerfile gains an esbuild worker bundle + `scripts/start-worker.sh`; install-smoke asserts six healthy services; docs updated (DEPLOYMENT, ENVIRONMENT_VARIABLES, GETTING_STARTED, info-site self-hosting) and `.env.example` gains optional `WORKER_*` vars. Verified end-to-end on a throwaway Postgres: recurring dispatch→claim→execute→complete with full transition audit, missed-tick incidents during worker downtime, all three sweeper paths, clean SIGTERM drain, and the production bundle under plain `node`.
- [2026-07-20] [Feature] Scheduling overhaul Phase 3 — orchestrator on the leased lifecycle (plan: `_plans/scheduling/PLAN.md`). **App**: new `POST /api/internal/jobs/claim` (atomic SKIP LOCKED claim stamping a 60s lease; replaces the mutating GET and the acknowledge step) and `POST /api/internal/jobs/heartbeat` (renews leases and returns per-job cancellation requests — UI cancel now reaches running containers); status/complete/fail routes gain timing-safe auth, ownership preconditions (wrong claimer → 409), CAS-idempotent semantics (duplicate terminal report → success, conflicting late report → 409), real `timed_out`/`cancelled` statuses, and structured stats; `jobs.result` updates are jsonb merges so concurrent `cronium.output()` writes can't be lost; acknowledge/release/orphaned/queue routes deleted. **Orchestrator (Go)**: stable hostname-based identity (no boot timestamp — the bug that made orphan recovery permanently blind); broken recovery machinery deleted (leases + the worker sweeper replace it); HTTP retry rebuilds requests per attempt (retried POSTs previously sent empty bodies); a lease-heartbeat loop (20s) cancels jobs on request and self-fences (aborts execution) when renewal fails past the lease window; completions are sent on background contexts, and undeliverable ones are spooled to the orchestrator-data volume and retried — graceful shutdown drains jobs before cancelling contexts, so deploys no longer lose in-flight results; stdout/stderr capture is capped per stream (1 MiB head+tail, omitted bytes reported); executor update channels block instead of dropping terminal messages (a dropped completion could previously report a failed job as succeeded); SSH multi-server fan-out deep-copies job metadata (data race) and keys results uniquely. Verified via go build/vet/test, app typecheck/lint/jest, and a live curl-driven orchestrator simulation covering the full claim→heartbeat→cancel→complete→idempotency cycle.
- [2026-07-20] [Feature] Scheduling overhaul Phases 4–6 — resumable workflow engine, schedule UI, deletion sweep (plan + full record: `_plans/scheduling/PLAN.md`, `_plans/scheduling/summary.md`). **Workflow engine (Phase 4)**: new `workflow_step_runs` table is the event-sourced source of truth; `src/lib/scheduling/workflow-engine.ts` replaces the ~1000-line in-memory promise-tree executor with an `advance()` reducer — per-run SKIP LOCKED serialization, steps settled from job rows, edge evaluation resolving impossible branches immediately as SKIPPED/UNSATISFIABLE (the old engine stalled 30 minutes on these), in-transaction step claiming with crash-safe job re-attachment, and run finalization with counts derived from steps. Runs survive any restart: advancement is driven by job-completion notifications plus a reconcile sweep and a boot pass. **Scheduled workflows now fire** (review C2): the dispatcher materializes `workflows.next_run_at` and starts runs on cadence. **UI (Phase 5)**: event form gains timezone, missed-run (catch-up) policy, overlap policy, and priority, plus live cron validation with a next-runs preview; cron expressions and the 10s interval floor validated at save; creating an event as ACTIVE schedules it immediately (M6); new schedule-incidents card on the event overview (`events.getScheduleIncidents`). **Sweep (Phase 6)**: deleted workflow-executor, job-scheduling-utils, multi-server-job-builder, execution-counter, job-polling-service, cleanupOldJobs, and orchestrator dead config; job list/stats counts fixed (were NaN — review D2); SSH circuit-breaker config honored. **Live chaos verification**: worker kill-9'd mid-workflow converged to a loud FAILURE on restart (lease expiry + cascade skip); the real orchestrator binary ran a scheduled bash job in a container end-to-end and honored a mid-run cancellation via heartbeat (~8s to container kill, `cancelled`/−2). Testing surfaced and fixed a real race: the executions-update route finalized cancelled jobs as FAILED, 409-ing the orchestrator's true completion — it now derives the same status semantics as `/complete`.
- [2026-07-20] [Fix] CI install-smoke failures on first real run (worker crash-loop + orchestrator unhealthy). **(1) Worker `Cannot find module '@cronium/ui'`**: tool plugins are `.tsx` modules carrying both server `execute()` logic and their config UI, so `initializePlugins()` pulls `@cronium/ui` into the worker bundle's import graph; esbuild's `--packages=external` left it as a bare require, and the runtime image contains neither the workspace package nor a transpiler for its TypeScript — the container crash-looped before its healthcheck could ever pass (reproduced locally via the full installer flow). Fixed by aliasing `@cronium/ui` to a bundled Proxy stub (`worker-stubs/ui.cjs`) that throws loudly if any worker code path ever actually invokes UI. **(2) Orchestrator `unhealthy`**: the health checker held its mutex across the Docker-daemon `Info` probe, so a daemon slowed by the crash-looping worker's churn blocked `GetHealth` → blocked `/health` → tripped the container healthcheck's 5s timeout — the orchestrator read as unhealthy precisely because a neighbor was thrashing. Probes now run outside the lock (results stored under a brief lock) and the daemon probe timeout is 15s. Verified: full from-source image build + installer run locally with the exact workflow assertions — all six services healthy, app health and first-run redirect green.
